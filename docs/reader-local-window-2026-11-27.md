## 审查发现及本轮修复

### 第一轮：调用链和局部失效传播

- `capture.js` 的导航 `read` 遍历 `data.rows()`，逐条调用 `ReaderPageIndex.fromBranch()` 和 `metadata()`；`source-file.js` 的 tree/page `rows()` 每条调用完整 `FastTextExporter.records()`。正文已丢弃不等于未转换。
- `page-index.js sample()` 每次对全部挂载消息做正文遍历及指纹；导航读取的 `check()` 和定位循环都调用它。`outline-tree.js setRows()` 重建整棵模型；DOM 只显示窗口不代表章节计算局部化。这些核心路径保持原样，以免污染改前测量。
- `center.js groupName()` 缺名时直接拼内部 ID；`stage()` 的异常退出丢掉节流器最后一条计数，并把局部来源错误抛到全队列。
- 新增两项回归先失败，再改名称解析、末次 `flush`、有限诊断及可隔离范围。保留角色/分支/完整性校验，损坏附件不改成“导入成功”。

### 第二轮：恢复边界、权限与真实失败

- 原 host 在短暂请求失败后标记 inactive；分钟唤醒只看 active，因此没人再查已接收的原回执。增加持久化的最多两次延后核对，间隔至少 5 秒/30 秒，尊重有效 `Retry-After`。进程内上传器原有的最多两次丢包重试保留，两个预算都有限。
- 延后尝试在既有 per-item 锁内重新读取任务、预占预算；服务唤醒仍用既有 alarms/offscreen host。排队不显示成功，也不让用户为每次短暂中断重复点击。浏览器关闭时不会执行；重开后按到期状态处理。旧的历史暂停任务不会被无条件强制恢复。
- 不自动重读失败来源、接受缺件/实时分享/冲突、变更目标或代用户确认追加。401/403/409/413/422/507、未知协议回执和带明确语义错误的 5xx 不重试；尝试耗尽保留包与诊断。
- 复查补出三项失败回归：未知异常原文泄漏到错误区域、不完整回执可触发新的发送、切账号后的旧回执可删除保留文件。改为有限文案、实际 HTTP 边界的收据结构校验、响应后再次核对设备和 owner-bound 写回。
- 一次定向测试暴露两项回归：旧的“状态改变”提醒被过度泛化；通用上传单测原本以 `{}` 表示无收据。恢复可辨认的固定状态提醒，将严格收据校验放在真实 host HTTP 边界，保留既有上传测试断言和语义。

### 第三轮：交付范围、界面状态与包复核

- 复查 scheduled recovery 在取消后不能执行，损坏预算不能无限唤醒，语义错误不能被临时 HTTP 状态覆盖；失败记录均保留。
- 实际 `panel.js` 的合成 DOM 测试核对：缺名不是“未归类”、选项值仍是原 UUID、项目筛选不隐藏不可用警告、原生 `details/summary` 保留 AI 预设入口。初次测试夹具使用了非 UUID 对话 ID，被原目标校验正确拒绝；改成合法合成 UUID，未放宽产品校验。
- 候选 **0.3.1** 单独打包，不更新原导出器版本，不携带测量探针。旧版测量包仍从固定 0.3.0 ZIP 生成，既不随候选变化，也不被混称为新架构。
- 这三轮覆盖本阶段代码与工具；四轮章节架构尚未实现，不能把本阶段审查当作整项整改已完成。
