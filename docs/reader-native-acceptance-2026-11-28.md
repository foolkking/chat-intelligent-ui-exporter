# 0.3.5 网页验收单（由用户执行，结果尚未填写）

要先试功能，不必先做所有技术实验：打开插件「导航」，在超过 100 轮的私人测试对话中从末尾跳到首轮，再去中间一个回答的二级、三级章节；打开「导入」，选原来缺名的两个来源项目，看能否自动补名。**不要提交生产导入**。看起来正常也请先保留下面的核对记录。

## 准备

- 记录 ZIP SHA-256、扩展管理页版本、Chrome/Edge 版本、缩放和窗口大小。原桌面目录名不代表其版本。不要卸载原扩展、迁移登录凭据或清浏览器存储。测试候选可用独立浏览器配置手动登录，装入**新解压目录**；不要在同一配置里用相同 ID 并装两版。
- 如能保留对照，在同一对话、分支、缩放和窗口大小，先记旧版远端失败现象再试候选（0.3.3 和 0.3.4 单独标明）。正在生成/保存/采集时不要做实验。关闭其他会控制滚动的扩展，记录是否开启 ChatGPT 项目侧栏。
- 普通导航不需要控制台。下面命令只在用户需要取证时使用，**不粘贴外来脚本，不打开浏览器调试权限**。在 ChatGPT 标签页的开发者工具 Console 选择 **Chat Reader 的 isolated world**，不是网页 `top`。打开「导航」，等完整目录加载。没有该上下文或只有部分目录就记录“未验证”，不要跳过认证。
- 不提供 HAR、Performance 原始追踪、页面源代码、原始报告库、对话/项目/文件名称、项目或消息 ID、URL、设备码及登录信息。需要截图时，仅保留插件层级、局部落点和状态，遮掉正文、标题、账号、头像、地址栏。诊断只在本机内存运行，不会上传。

## E1：原生 URL 是否真的载入目标？

1. 在原标签页执行 `ReaderSiteCheck.index()`，取得轮次数。`ReaderSiteCheck.targets(1)` 列出第 1 轮中每条消息的**本次编号 `n`**、角色及挂载情况，不输出消息 ID 或正文。选择远端提问、回答各一个。
2. 执行 `const ticket = await ReaderSiteCheck.route(n)`（用数字替换 `n`）。这是主动实验：原页不刷新，新标签带上 `message` 参数，保留项目路径、其他参数和片段。浏览器拦截弹窗时记“未执行”。在原标签 `copy(JSON.stringify(ticket))`，**票据只在自己两个标签间使用，不发回**。
3. 新标签**先不要滚原文、不要点树节点**，先看 ChatGPT 自己停在哪里。打开导航并等待完整目录，在其隔离控制台输入 `await ReaderSiteCheck.routeResult(票据对象)`（粘贴上一步本地复制的 JSON 对象）。实际对照：`sameTarget`、`sameIndex`、`sameBranch`、`visibleStart`、`stable`，以及 `readingLineErrorPx`。若分支无法独立证明，`sameBranch:null`，不能填通过。`queryRetained:false` 可以是 ChatGPT 规范化了 URL，不等于失败；仅地址改变也不等于成功。票据十分钟有效。
4. 在普通对话、项目内对话、跨历史页、编辑过的分支重复；新建标签是一次**文档载入**，本实验不证明原标签可无刷新导航。返回原标签，核对原分支和草稿仍在。不测试已有采集/上传中的强制刷新。候选没有把未经验证的 URL 路由设成自动导航。

## E2：原生无刷新定位是否可用？

在原页完整目录中，用 `ReaderSiteCheck.targets(轮号)` 找到 `no-identified-mount`、`shell-only`、`css-skipped` 或 `body-or-layout-pending` 的远端回答，执行 `await ReaderSiteCheck.native(n)`。这是**隔离实验**：不使用几何历史搜索或外壳滚动为原生接口兜底。需要当前 API 映射、已挂载见证、目标正文、正确位置和稳定核验；能力存在、私有方法返回或外壳出现都不算成功。

| 结果 | 能证明什么 |
|---|---|
| `message` + `native:"requested"`，且亲眼核对正确 | 本次目标经原生行准备并完成正文精确核验；仍不是所有分页/分支都可用 |
| `already-rendered` | 所选目标正文已挂载，不是有效的远端原生实验 |
| `not-loaded` / `no-witness` / `ambiguous` | 当前原生列表尚未证明目标、当前行或唯一映射；不是远端精确成功 |
| `uncancellable` / `unsupported` / `budget` | 已探测形状不适用，或成本超限；普通点击可走有界回退，不关闭平台保护 |
| `unmounted` / `body` / `hidden` / `changed` / `cancelled` | 未能完成核验或被打断，不计成功 |

`no-identified-mount` 表示**没有可证明的**挂载点；无法排除页面上还有完全匿名的占位，不要将它误报成已确定的 ChatGPT 内部状态。

## E3：真实长对话，分别完成 30 次消息和 30 次章节定位

1. 在隔离控制台执行 `ReaderSiteCheck.begin()`，然后正常在插件树上点击。按下表在每一列至少分配五次。记录**全部尝试**，不只取成功例。

   | 路径/情况 | 消息定位 | 章节定位 |
   |---|---:|---:|
   | 末尾 → 首部 | 5 | 5 |
   | 首部 → 远端 | 5 | 5 |
   | 中间轮与跨历史页 | 5 | 5 |
   | 折叠外壳、延迟渲染 | 5 | 5 |
   | 多回答、重复标题、二/三级标题 | 5 | 5 |
   | 复杂 DIL、公式、长代码、图片/文件引起的布局变化和往返 | 5 | 5 |

2. 核对**真实正文开头**或**目标标题和起始内容**，核对层级/父章节/同名项与分支；只看到外壳、角色标签或回答不算章节成功。落点应在输入框上方有效阅读区下部，首尾不能再滚时允许可见的边界位置。检查短暂高亮、是否被遮挡、图片加载后是否回弹。错误定位目标为零；准确率尚无实测值。
3. 每次完成后可在控制台标记刚才的**人工判断**：`ReaderSiteCheck.mark("exact")`；其他值为 `"answerOnly"`、`"wrong"`、`"failed"`、`"cancelled"`。第二参数可填 `true` 表示亲眼看见回弹，例如 `ReaderSiteCheck.mark("wrong", true)`。不标记的记录是 `unreviewed`，不当作通过。也可线下按次记录，不必在每次点击间切换控制台。
4. 额外试：定位期间滚轮/触屏/键盘取消、快速连点、关闭插件、切换分支；最后有效窗口应不被旧任务覆盖。目标轮 `k` 的范围是 `[k−1,k,k+1,k+2]`，首尾不补齐；窗口外只有轮次标题，全文查找和附件仍可访问。普通滚动不应触发整段历史章节解析。
5. `copy(JSON.stringify(ReaderSiteCheck.end()))` 得到最多最近 128 条脱敏记录：分类型人工计数及每次策略、阶段耗时、扫描/正文核对数、落点偏差和校正数。`outcomes` 是引擎分类，不是人工成功率。精确成功率 = 人工精确 / 有判定的非取消尝试；降级、失败、错误、取消及未判定另外计数。`performance.memory` 可用时为**网页 JS 堆估计 MiB**，不是插件独占内存；事件延迟仅统计浏览器报告的事件，不能从零条样本推出零延迟。另记索引期间实际滚动、点击是否流畅。

## E4：截图中两项缺名的原因

1. 在导入页选择**原来出问题的 ChatGPT 标签页**。先勾几条对话、切项目筛选/翻页，再展开 ChatGPT 项目列表。在来源标签的隔离控制台执行 `ReaderSiteCheck.projects()` 可看到当前 DOM 提供了哪些**类型**的名称证据。
2. 在扩展导入页自己的 DevTools 执行 `ReaderProjectReport()`；如果是在统一工作区，选择扩展 **`frame.html` 导入 iframe 的页面上下文**，如果是原生侧栏则选 `center.html`。看 `selectedFilter` 找到当前选中项目，分别记录两项的 `observed/resolved/named/localAlias/labelAgrees`。不要发原始目录，只需发这些字段。
3. `project-link/control/heading/metadata/document`（实际输出均有 `project-` 前缀）/ `export-metadata` 是来源证据；`workspace-cache` 是同工作区缓存；`missing` 是当前无显式名称；`no-server-label` 是已读取的项目文档不含可用标记；`conflict` 表示显式证据互斥；`size-limit`、`access`、`unavailable` 分别表示有界读取、拒绝/限流或响应不可用。`named:true` 但可见行 `labelAgrees:false` 才提示传递/呈现层问题。不能把之前截图直接诊断成某一种失败。
4. 名称晚到后验勾选、分页、滚动、目标下拉、草稿与已确认任务都未改变。不凭同名合并项目，已有资料不移动。确实无名才用「别名」；清空并保存可移除。测试另一工作区不应复用名称；本机导出包按文件指纹隔离，不使用网页账号缓存。网页目录应一直标明局部覆盖。

**最小反馈**：版本、浏览器版本、E1/E2 状态、E4 两项的脱敏原因、E3 消息/章节各类次数；如有一次错位，附该次 `last` 数字和经遮盖的落点截图即可。没有做的项写“未测”。本轮没有真实网页截图、服务端导入回执或线上性能结论。
