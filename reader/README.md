# Chat Reader 浏览器客户端

## 核心整改候选 — 2026-11-26，尚未发布

**本轮变更：** 追加仍默认全选；输入轮次后点击「应用」默认**仅选此区间**，也可加入或排除。分页按较早页的原始顺序去重；只有对象键顺序、请求标记和记录触碰时间不构成冲突，正文、资源、分支及未知字段仍受校验。读取失败保留已测量计数和有限原因，不把未生成的包标成可续传。目录合并已核对消息的结构化标题；章节文字不能唯一对应、分支变化或分页停止前进时，不报告已定位。网页项目目录始终是已挂载项，不代表完整账号。真实对话、长距离跳转与最终提交回执由使用者在测试实例验收；不要用线上实例试包。

**按来源项目保存：** 在「确认 Reader 保存位置」中，各行可选任意活动项目或未归类。已有同名项目可直接选用；没有时可以按来源名在 Reader 确认新建，确认后只回填发起行。只含编号的来源显示一条已选对话供辨认，不用编号猜名称。旧 Reader 可打开侧栏手动新建，返回刷新。新建是 Reader 登录会话的独立操作，不扩张设备令牌权限，不会自动开始导入或移动已保存的对话。

这是现有 Reader 的客户端，不是第二个文件库。Reader 保存账号、资料、项目与导入收据；本 Fork 负责来源读取、转换和浏览器交互。原导出器与 Reader 客户端独立打包，上游包版本不随 Reader 版本改变。复用 `extension/fast-text.js`，保留 MIT、第三方声明和固定本地 `fflate`，不加载远程代码。

本候选须经过精确提交的完整 CI 和实例安装包核验后才可交付。两仓沿用 `codex/reader-extension`。当前生产与已发布安装包仍以 Reader 的 `PROJECT_STATE.md` 和发布回执为准，不能用本地截图或旧提交 CI 认证当前工作树。

**本机人工验收包不是正式分发包。** 相同 `0.3.0` 和扩展 ID 不保证相同字节，请以本轮 ZIP SHA-256 区分。不要覆盖已有安装目录或移植个人浏览器凭据。验证超过 250 条的追加和新诊断时，隔离实例需要此轮 Reader API、worker 和 Web；只更新插件不会更新服务器。

### 界面与连接

- ChatGPT 私人页面折叠时只有「三横线／保存／更多」一组控件；三横线打开「导航／资料库／导入」工作区，同一个保存节点迁入内部，不挤占正文、不重复显示外部保存条。没有当前对话时显示资料库。普通网站不注入；主动点工具栏才打开固定导入中心的原生侧栏，浏览器不支持时回退固定独立页。
- **资料库只搜显示标题或项目名称**，保留最近／置顶、项目筛选和分页；附件不占独立结果。点对话打开 Reader，更多菜单提供已有轻量操作与「交给 AI」。
- 连接时在扩展自己的页面显示短码，不弹登录窗、不在插件内收集密码。到 Reader → 账号安全 → 浏览器插件输入短码，核对账号／设备／权限后批准。短码 10 分钟有效；仅知道短码不能领取设备凭据。原 PKCE 与已有有效设备兼容，网页可撤销单设备。
- Reader 私有列表、短码和设备凭据不进入 ChatGPT DOM。只有明确启用项目名展示时，保存按钮才显示所选 Reader 项目名。

### 当前对话：定位、保存、交接

目录无需 Reader 登录：轮次→提问/每个回答→各级章节，展开与定位操作分开，当前章节独立高亮。Fork 和 Reader 共用新版 DOM 身份/可见正文适配，排除隐藏历史和无障碍角色标题。本地搜索当前正文的每处命中，附件定位所属消息。只在身份、可见和稳定检查通过时报告精确定位；不可确认的文件目标明确退到所属消息。目录不完整时标明部分，手动滚动取消旧跳转。

确认默认目的地后，原「保存到 Reader」仍一次点击。重复内容由 Reader 实际来源绑定与收据判定，不按标题认领；只有共同前缀得到验证才能在末尾追加。缺件、分支或原文改变、实时分享需要核对，不自动覆盖、移动或另存。

完整采集移除旧 8/32 MiB JSON、16 MiB 单附件、100 MiB 包、2 MiB 正文及 50,000 条消息门槛，采用字节范围索引、按需正文、OPFS 分块打包和 4 MiB 续传。读取、核对、转换、附件、封包、上传保留各自累计计数、耗时和脱敏诊断；服务器确认偏移不与本地读取量混称，总量未知不伪造百分比。服务器账号配额、归档校验、真实内存与空间保护仍生效，不承诺无限物理资源。

保存和选择追加绑定各自的尝试；切任务、来源或账号不能沿用上一项的读数。无法解析的资源提示与已下载附件分开计数，错误详情直接显示停止阶段。系统完整性错误不鼓励重传同一包。回到来源页只读取原追加收据：待确认、新版确切结果、部分结果及无完整性明细的旧收据分别展示，不替用户确认。

定位按实际滚动容器换算坐标，包括 `column-reverse` 的负 `scrollTop`。对已挂载章节或虚拟窗口都要重新核对当前身份、实际可见范围及连续稳定帧；估算位置或调用了滚动方法本身均不是成功。

更多菜单中的「选择内容并追加到…」默认全选，支持轮次、角色、区间、Shift、跨页保留、全文搜索及按需预览；默认选择不意味着自动提交。新 Reader 的 `selective_append_ranges` 能力允许超过250条的一次原子复核与追加；旧服务明确要求升级，不截断或自动分成多次写入。设备仅暂存片段，目标和最终追加仍须登录 Reader 网页确认。另一设备先追加时保留勾选、重新确认新末尾。默认目标只影响新建，不把已存对话移到另一个项目。

「交给 AI」默认采用完整对话、可导出的附件原文件及已有 Current/Index；已保存账号预设不会被覆盖。使用服务端安全文件名 `对话名.context.zip`，生成后可分别下载上下文包和接续 Skill；Skill 取消或不可用无需重做上下文包。内容不会自动传回 ChatGPT。

### 选择批量导入

所有入口共用 `center.html`：**选择来源 → 勾选对话 → 确认 Reader 目标 → 查看任务**。ChatGPT 中嵌入同一工作区，不默认新开标签；资料库与导入私有 frame 分别授权且并存，切换和收起不销毁原队列，路由改变需重新核实来源。项目入口只预定位，不自动勾选或读取。

| 来源 | 实际能力与边界 |
|---|---|
| 获准 ChatGPT 私人标签页 | 用户明确选页后读取已挂载的目录链接。只允许选择已发现项，不提供“整个账号／项目”。账号与工作区无法明确核实时禁止批量读取；网页接口与字段的真实账号适用性仍需验证。 |
| 本机官方 ZIP / `conversations.json` | 在本机读取唯一对话文件、验证 ZIP 与资源归属。只有确认后的所选对话及相关附件发送给 Reader，原包及未选目录不上传。归属未知不等于未归类；仅完整解析且归属明确的本地目录开放“此导出包内整个项目”。 |

每页 50 行不是总量上限。支持本页／筛选结果选择、跨页跨项目保留、查看及移除已选。目标默认逐来源分组核对，也可统一；来源项目与 Reader 项目不混称，同名不自动合并。记住映射须显式勾选，按来源范围、Reader 实例与账号隔离。

确认后固定来源、目标、附件策略和每条幂等键，一次处理一条。关闭中心后已受理任务继续，未发送计划保留；重新打开需核对原文件或原工作区，结果不明先查原回执。暂停不取消已受理任务；取消与恢复互斥，不能把尚不确定的结果当作未上传。失败只重试原收据，冲突可明确另存或跳过本次并保留原件。新选择不能静默覆盖未完成计划；换账号／工作区暂停。

### 服务端兼容与验证边界

先交付配套 Reader **API、worker 和 Web**，单一迁移 head `20261125_0065`，再更新插件。按能力检查 `catalog_names`、`resumable_capture`、`source_lookup`、`import_retry`，不静默回退旧全文查询或整包上传。内部长正文草稿不能交给旧 worker；0064→0065 使用完整维护，不能按无迁移快路径升级。

## 打包、安装与更新

```powershell
# 固定目标实例；输出必须是全新目录。不需要 npm install 来打包。
node scripts/package-reader.cjs https://reader.example.test E:\chat-reader-temp\reader-private-build --zip
```

分发时提供绑定实际实例的 `chat-reader-0.3.0.zip` 和 **这个安装包**的 SHA-256，而不是示例域名包。用户无需编译：核对可信交付摘要，解压到长期保留的目录，在 Chrome／Edge 扩展管理开启开发者模式，加载直接含 `manifest.json` 的目录。

稳定内测 ID 仍为 `gihbiofiiflkckcmomddkkjkoifkddfi`，绿色 cr 图标不会改变 ID。更新已有解压安装时，先完成或暂停来源读取，用已核验的新包替换原安装目录的程序文件，再在扩展管理点「重新加载」并刷新 ChatGPT 标签。不要删除扩展的存储或先卸载以清空授权、恢复包和计划；未受理的来源读取关闭后需要重新读取。解压安装不具有商店自动升级机制。

**公开 Fork 的交付：** 不设置、上传或公布私人 Reader 地址。成功的推送 CI 用固定示例地址构建两次，只上传该参考 ZIP 的校验文件，制品名 `reader-reference-<SHA>-<运行 ID>-<尝试>`。运维从**同一仓库、同一提交、同一成功运行及尝试**取这个文件并校验下载的 Actions 制品，然后在对应检出的代码中绑定实际 HTTPS 地址打包：

```powershell
# READER_DISTRIBUTION_ORIGIN 预先从可信部署配置设置；路径为本次新目录和已取得的精确 CI 参考校验文件。
node scripts/package-reader.cjs $env:READER_DISTRIBUTION_ORIGIN "$T\extension" --zip
node scripts/verify-reader-distribution.cjs "$T\chat-reader-0.3.0.zip" "$R\chat-reader-0.3.0.zip.sha256"
```

核验器检查实际 ZIP 是打包器生成的规范字节、配置、主机权限与 CSP 均绑定该实例，再只把这三处绑定还原到示例地址，要求还原后的**整个 ZIP**与 CI 摘要相同。可执行代码、权限、图标或许可文件不符均拒绝。不要用安装包旁自生成的摘要代替 CI 的参考摘要；两个不同地址的 ZIP 摘要本来就不同。只有明确配置 `READER_PUBLIC_ORIGIN` 的**私有仓库**才另在 Actions 中生成实例包。`--test-only` 仅作本地实验，不用于向用户交付。

实例须在 API **与 worker** 登记 `READER_EXTENSION_IDS`，只装可信构建；公开 ID 不是安装包签名。不需要 `<all_urls>`、Cookie 或浏览历史权限，不上传 ChatGPT 登录凭据。重访来源时，仅显式查找或允许本设备自动识别后才发送当前来源 ID；绑定存在不代表最新内容一致。换 Reader 账号不能沿用旧账号的打开链接。
